# المخطط الهندسي والتنفيذي الشامل لمنصة التسميع القرآني وتصحيح التجويد بالذكاء الاصطناعي

> **نوع المشروع:** منظومة متكاملة (ويب PWA + تطبيق جوال Android/iOS + خادم مركزي + محرك ذكاء اصطناعي مستضاف ذاتياً)  
> **النطاق:** التسميع الذكي، تتبع التلاوة كلمة بكلمة، اكتشاف أخطاء الحفظ لحظياً، خطط الحفظ والمراجعة، وتصحيح أحكام التجويد بالذكاء الاصطناعي.

---

## 1. الرؤية الهندسية والمعمارية العامة (High-Level Architecture)

لتحقيق أداء يضاهي التطبيقات العالمية مع استقلالية تقنية كاملة عبر **نماذج ذكاء اصطناعي مفتوحة المصدر مستضافة ذاتياً (Self-Hosted AI)**، تُفصل المنظومة إلى **4 طبقات مستقلة قابلة للتوسع أفقياً**:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        طبقة تطبيقات المستخدم (Clients)                      │
│  ┌─────────────────────────────────┐   ┌─────────────────────────────────┐  │
│  │   تطبيق الويب (Next.js / PWA)   │   │ تطبيق الجوال (React Native/Expo)│  │
│  │  • AudioWorklet (16kHz PCM)     │   │  • Native Audio Stream + JSI    │  │
│  │  • IndexedDB / Local Cache      │   │  • SQLite (Offline-First Sync)  │  │
│  └───────────────┬─────────────────┘   └────────────────┬────────────────┘  │
└──────────────────┼──────────────────────────────────────┼───────────────────┘
                   │ REST API (HTTPS) + بث صوتي لحظي (WebSocket / WebRTC)
                   ▼                                      ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│               بوابة الجلسات والخادم المركزي (Core Backend Gateway)           │
│                     FastAPI (Async Python) + WebSockets                     │
│  ┌──────────────────────┐ ┌───────────────────────┐ ┌────────────────────┐  │
│  │ مدير الجلسات اللحظية │ │ محرك المطابقة والأخطاء│ │ خدمات الحفظ والخطط │  │
│  │ Session State (Redis)│ │ Fuzzy Quran Aligner   │ │ FSRS & Analytics   │  │
│  └──────────┬───────────┘ └───────────▲───────────┘ └─────────┬──────────┘  │
└─────────────┼─────────────────────────┼───────────────────────┼─────────────┘
              │ gRPC / Internal Queue   │ النصوص والرموز الصوتية│
              ▼                         │                       ▼
┌───────────────────────────────────────┴──────┐  ┌───────────────────────────┐
│   خادم الذكاء الاصطناعي المستضاف (GPU Node)  │  │ طبقة البيانات والتخزين    │
│  • Silero VAD (كشف الكلام وتصفية الصمت)      │  │ • PostgreSQL (البيانات)   │
│  • محرك الحفظ: Whisper-Quran / NeMo ASR      │  │ • Redis (الذاكرة اللحظية) │
│  • محرك التجويد: Muaalem QPS Multi-Level CTC │  │ • S3 / MinIO (ملفات الصوت)│
└──────────────────────────────────────────────┘  └───────────────────────────┘
```

### لماذا هذه المعمارية تحديداً؟
1. **كود مشترك بنسبة ~70% بين الويب والجوال (Monorepo):** باستخدام **Turborepo** بلغة **TypeScript**، يشترك تطبيق الويب (`Next.js`) وتطبيق الجوال (`React Native`) في نفس حزمة منطق الأعمال، إدارة حالة الجلسة، هيكلية صفحات المصحف، ونظام المزامنة.
2. **عزل خوادم الـ GPU عن خادم التطبيقات:** خادم التطبيقات (FastAPI) خفيف جداً ويدير آلاف الاتصالات، بينما تُعزل نماذج الصوت والتجويد في حاوية استدلال مستقلة (GPU Worker) يمكن ترقيتها أو مضاعفة عددها حسب الضغط دون المساس بقاعدة البيانات أو منطق التطبيق.
3. **تصميم يدعم العمل دون إنترنت (Offline-First):** بيانات المصحف الكاملة، الخطط اليومية، وسجل الأخطاء تُحفظ محلياً في `SQLite` على الجوال و`IndexedDB` على الويب، وتُزامن تلقائياً فور توفر الاتصال.

## 2. المكدس التقني المعتمد (Production Tech Stack)

| المكوّن | التقنية المختارة | مبررات الاختيار الهندسية |
| :--- | :--- | :--- |
| **إدارة المستودع البرمجي** | **Turborepo (Monorepo)** | توحيد الحزم المشتركة (`@quran/shared`, `@quran/mushaf-engine`) بين الويب والجوال. |
| **تطبيق الويب** | **Next.js + React + TypeScript + Tailwind CSS** | أداء عالٍ، دعم كامل للغة العربية (RTL)، دعم التثبيت كتطبيق PWA، والتقاط الصوت عبر `AudioWorklet`. |
| **تطبيق الجوال** | **React Native (Expo Custom Dev Client)** | أداء أصلي (New Architecture / JSI)، مكتبة `op-sqlite` السريعة، وبث صوتي منخفض التأخير لـ Android و iOS. |
| **الخادم المركزي (Backend)** | **Python (FastAPI + Uvicorn Async)** | تكامل أصلي مع منظومة الذكاء الاصطناعي ومعالجة النصوص العربية، ودعم ممتاز لـ WebSockets غير المتزامنة. |
| **بروتوكول البث الصوتي** | **WebSockets (ثنائي الاتجاه) / LiveKit WebRTC** | البدء بـ WebSockets الثنائية لإرسال شرائح PCM (كل 250ms)، مع قابلية الترقية لـ LiveKit عند التوسع المليوني. |
| **قاعدة البيانات الرئيسية** | **PostgreSQL 16** | تخزين حسابات المستخدمين، الجلسات، سجل الأخطاء التفصيلي، وخطط المراجعة بدقة علائقية عالية. |
| **الذاكرة اللحظية** | **Redis 7** | حفظ مؤشر التلاوة الحالي وسياق الآية لكل جلسة نشطة بسرعة أجزاء من المللي ثانية. |
| **تخزين التلاوات الصوتية** | **MinIO (Self-Hosted S3)** | حفظ مقاطع التلاوة المرفوعة كل 20 ثانية ودمجها عند طلب المستخدم مشاركة تلاوته أو مراجعتها. |

## 3. هندسة البيانات القرآنية ورسم المصحف (Quranic Data Layer)

نعتمد على المصادر القياسية مفتوحة المصدر من **منصة QUL (Quranic Universal Library)** ومجمع الملك فهد لطباعة المصحف الشريف:

1. **التمثيل المزدوج لكل كلمة قرآنية (Dual-Script Tokenization):**
   لكل كلمة في القرآن الكريم (77,429 كلمة) معرّف فريد `word_global_id` وتُخزن بأربع صيغ متلازمة:
   * **الرسم العثماني (`text_uthmani`):** للعرض البصري المطابق للمصحف (مثال: `ٱلصَّلَوٰةَ`).
   * **النص الإملائي المشكول (`text_imlaei`):** للمطابقة الصوتية مع التشكيل وأواخر الكلم (مثال: `الصَّلَاةَ`).
   * **النص الإملائي المجرّد (`text_normalized`):** منزوع التشكيل وموحّد الهمزات والألفات للمطابقة السريعة والبحث الصوتي (مثال: `الصلاة`).
   * **الرموز الصوتية التجويدية المرجعية (`qps_phonemes`):** التمثيل الصوتي القياسي للكلمة شاملة أحكام الوصل مع الكلمة التي تليها (للمقارنة في محرك التجويد).
2. **تخطيط الصفحات والخطوط:**
   * **وضع مصحف المدينة (15 سطراً):** مطابق تماماً للمصحف الورقي (604 صفحات) لتثبيت الحفظ البصري (المواضع في الصفحة واليمين واليسار).
   * **الوضع المتكيّف (Adaptive Mode):** عرض مرن بآيات مستقلة مع إمكانية تكبير الخط وإظهار التفسير أو الترجمة.
3. **شبكة المتشابهات اللفظية (`Mutashabihat Graph`):**
   * جدول يربط الآيات المتشابهة في نفس السورة أو في سور أخرى لتنبيه الحافظ أثناء التسميع ومنع انتقال المؤشر بالخطأ إلى السورة المشابهة.

## 4. هندسة محرك الذكاء الاصطناعي المستضاف ذاتياً (Self-Hosted AI Pipeline)

تُبنى طبقة الذكاء الاصطناعي من **مسارين متكاملين** يعملان على خادم GPU خاص بك:

### أ. المعالجة الصوتية المسبقة (Audio Front-End)
1. يلتقط التطبيق الصوت بتردد **16,000 Hz، قناة أحادية (Mono)، 16-bit PCM**.
2. يمر الدفق عبر نموذج **Silero VAD** (خفيف جداً يعمل في أقل من 1ms):
   * يتجاهل فترات الصمت والتنفس (يمنع "هلوسة" نماذج Whisper عند الصمت).
   * يرسل المقاطع النشطة فقط إلى محرك الاستدلال في نافذة متزلقة (Sliding Buffer).

### ب. المسار الأول: محرك تتبع الحفظ اللحظي (Word-Level Streaming ASR)
نصمم طبقة الاستدلال بنظام **Adapter Pattern** يدعم مستويين من النماذج مفتوحة المصدر المستضافة ذاتياً:

* **المستوى الأول (للبناء السريع والخوادم المتوسطة — بطاقة GPU واحدة مثل RTX 4090 أو NVIDIA L4):**
  * استخدام نموذج **`MaddoggProduction/whisper-l-v3-turbo-quran-lora-dataset-mix`** (المبني على معمارية Whisper Large v3 Turbo السريعة والمدرّب على التلاوات القرآنية مع التشكيل) أو **`wasimlhr/whisper-quran-v1`** (ذو معدل خطأ WER منخفض جداً ~5.35%).
  * تحويل النموذج إلى محرك **CTranslate2 (`faster-whisper`)** بدقة `FP16` أو `INT8` مما يضاعف السرعة 4 إلى 6 مرات مع استهلاك ذاكرة VRAM أقل من 3–5 جيجابايت!
  * تطبيق خوارزمية **LocalAgreement-2 Streaming** لإخراج الكلمات المؤكدة كل **250–400 مللي ثانية** أثناء التلاوة المستمرة.

* **المستوى الثاني (للتوسع المؤسسي لآلاف المستخدمين في نفس اللحظة):**
  * تشغيل نموذج **NVIDIA NeMo Stateful FastConformer-CTC / Hybrid RNNT** مخصص للقرآن عبر **NVIDIA Triton Inference Server**.
  * يدعم الذاكرة المؤقتة للتنشيطات (Activation Caching) بزمن استجابة **80–160 مللي ثانية** وقدرة استيعاب مئات الجلسات المتزامنة على بطاقة GPU واحدة.

### ج. المسار الثاني: محرك تقييم وتصحيح أحكام التجويد (Tajweed & Phonetics Engine)
لتصحيح التجويد (وليس مجرد الكلمات)، لا يكفي تحويل الصوت إلى نص عربي عادي؛ بل نعتمد المعمارية العلمية الأحدث في المصادر المفتوحة:
* **النموذج المرجعي:** معمارية **Multi-Level CTC** المبنية على **`facebook/w2v-bert-2.0`** والمطوّرة في مشروع **`obadx/quran-muaalem` (`muaalem-model-v3_2`)** والمصدّرة أيضاً بصيغة **ONNX INT8** عالية السرعة.
* **كيف يكتشف أخطاء التجويد؟**
  1. يحوّل النموذج الصوت المنطوق مباشرة إلى **الخط الصوتي القرآني (Quran Phonetic Script - QPS)** الذي يرمّز كل حرف مع صفته وزمنه.
  2. يقيس المحرك بدقة:
     * **أزمنة المدود:** المد الطبيعي (حركتان)، المد المتصل/المنفصل (4-5 حركات)، والمد اللازم (6 حركات) عبر حساب عدد الإطارات الزمنية (CTC Frame Duration) نسبةً لسرعة تلاوة القارئ نفسه!
     * **أحكام النون الساكنة والتنوين والميم:** الغنّة وزمنها، الإدغام بغنة وبغير غنة، الإخفاء الحقيقي والشفوي، والإقلاب.
     * **صفات الحروف:** القلقلة، التفخيم والترقيق (مثل لام لفظ الجلالة والراءات وحروف الاستعلاء).
  3. **ملاحظة هندسية وتنظيمية مهمة:** قبل الإطلاق التجاري، يتم التدقيق في رخصة كل وزن نموذج مستخدم (حيث تتوفر نماذج ومجموعات بيانات برخص مفتوحة بالكامل مثل MIT وApache-2.0 مثل `MohamedRashad/Quran-Recitations` و`Buraaq/quran-md-ayahs` وإصدارات MIT من النماذج، مع إمكانية إعادة التدريب الداخلي الكامل على خوادمك لضمان ملكية تجارية خالصة 100%).

## 5. خوارزمية المطابقة الذكية واكتشاف الأخطاء (Alignment & Mistake Engine)

هذا المحرك هو "العقل المنطقي" الذي يحول مخرجات الذكاء الاصطناعي إلى تجربة تسميع دقيقة خالية من الإزعاج:

### 1. آلة الحالة لجلسة التلاوة (Session State Machine)
* **الحالة (1) — التعرّف الحر على الموضع (`SEARCHING`):**
  * إذا بدأ المستخدم القراءة دون تحديد صفحة، يبحث المحرك في فهرس ثلاثيات الحروف والكلمات (**Inverted N-Gram Index**) لكامل القرآن (6,236 آية).
  * عند وجود تشابه بين سورتين (متشابهات)، يحتفظ المحرك بـ "قائمة المرشحين المحتملين" (`Candidate Beams`) لحين نطق الكلمة الفاصلة فيحسم السورة والآية تلقائياً.
* **الحالة (2) — التتبع المقيد بالمؤشر (`TRACKING`):**
  * بمجرد تثبيت الموضع عند الكلمة `i`، يفتح المحرك نافذة بحث موضعية `[i - 4, i + 6]`.
  * يقارن الكلمات المنطوقة بالكلمات المتوقعة عبر خوارزمية **Dynamic Programming Sequence Alignment (المسافة النصية الموزونة صوتياً)** التي تراعي التقارب الصوتي العربي (مثل التاء والطاء، أو الذال والزاي).

### 2. مصفوفة تصنيف الأخطاء والتعامل مع السلوك الطبيعي
| السلوك المرصود | كيف يتصرف المحرك؟ | الأثر في واجهة المستخدم |
| :--- | :--- | :--- |
| **نطق الكلمة الصحيحة** | تقديم المؤشر `i + 1` فوراً | كشف الكلمة المخفية بسلاسة وتلوينها بلون التقدم. |
| **تخطي كلمة أو آية (`SKIP`)** | رصد تطابق الكلمة المنطوقة مع `i + 1` أو `i + 2` دون نطق `i` | اهتزاز خفيف + تنبيه صوتي اختياري + تلوين الكلمة المتخطاة بالأحمر. |
| **استبدال كلمة بأخرى (`SUBSTITUTION`)** | عدم تطابق الكلمة المنطوقة مع `i` ولا مع نافذة التردد | إيقاف المؤشر أو إظهار تلميح ذكي وتظليل الكلمة بالأحمر البرتقالي. |
| **إعادة القارئ لجزء سابق (`BACKTRACKING`)** | تطابق الكلمات المنطوقة مع `[i - 4 .. i - 1]` لتصحيح نفسه | يرجع المؤشر بذكاء مع القارئ **دون احتساب خطأ جديد**. |
| **البسملة / الاستعاذة / صدق الله العظيم** | قائمة عبارات مستثناة خارج النص المتتبع | يتعرف عليها المحرك ويتجاوزها دون إرباك مؤشر الآيات. |
| **خطأ تجويدي (`TAJWEED_MISTAKE`)** | اختلاف رمز QPS المنطوق عن الرمز القياسي للحكم | تلوين موضع الحرف بلون الحكم التجويدي مع بطاقة توضيحية للحكم الصحيح. |

## 6. تصميم قاعدة البيانات الأساسية (Core Database Schema)

```sql
-- 1. بيانات المصحف المرجعية
CREATE TABLE quran_ayahs (
    id SERIAL PRIMARY KEY,
    surah_number SMALLINT NOT NULL,
    ayah_number SMALLINT NOT NULL,
    page_number SMALLINT NOT NULL,
    juz_number SMALLINT NOT NULL,
    text_uthmani TEXT NOT NULL,
    text_normalized TEXT NOT NULL
);

CREATE TABLE quran_words (
    id SERIAL PRIMARY KEY,           -- 1 .. 77429
    ayah_id INT REFERENCES quran_ayahs(id),
    word_position SMALLINT NOT NULL, -- ترتيب الكلمة في الآية
    page_number SMALLINT NOT NULL,
    line_number SMALLINT NOT NULL,   -- السطر في مصحف المدينة (1..15)
    text_uthmani VARCHAR(120) NOT NULL,
    text_imlaei VARCHAR(120) NOT NULL,
    text_normalized VARCHAR(120) NOT NULL,
    qps_reference TEXT               -- التوصيف الصوتي التجويدي القياسي
);

-- 2. جلسات التلاوة والتسميع
CREATE TABLE recitation_sessions (
    id UUID PRIMARY KEY,
    user_id UUID NOT NULL,
    mode VARCHAR(30) NOT NULL,       -- 'MEMORIZATION', 'READING', 'TAJWEED_PRACTICE'
    start_word_id INT REFERENCES quran_words(id),
    end_word_id INT REFERENCES quran_words(id),
    words_recited_count INT DEFAULT 0,
    accuracy_score NUMERIC(5,2),
    tajweed_score NUMERIC(5,2),
    audio_url TEXT,                  -- رابط التسجيل الصوتي المدمج للجلسة
    duration_seconds INT DEFAULT 0,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 3. سجل الأخطاء التفصيلي (لرسم الخريطة الحرارية للأخطاء ومراجعتها)
CREATE TABLE session_mistakes (
    id UUID PRIMARY KEY,
    session_id UUID REFERENCES recitation_sessions(id) ON DELETE CASCADE,
    user_id UUID NOT NULL,
    word_id INT REFERENCES quran_words(id),
    mistake_type VARCHAR(40) NOT NULL, -- 'SKIPPED', 'SUBSTITUTED', 'DIACRITIC', 'TAJWEED_MADD', 'TAJWEED_GHUNNAH'...
    expected_token VARCHAR(120),
    spoken_token VARCHAR(120),
    audio_timestamp_ms INT,            -- موضع الخطأ داخل التسجيل الصوتي
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 4. نظام المراجعة المتباعدة وخطط الحفظ (FSRS Spaced Repetition)
CREATE TABLE memorization_progress (
    user_id UUID NOT NULL,
    ayah_id INT REFERENCES quran_ayahs(id),
    stability FLOAT DEFAULT 0,
    difficulty FLOAT DEFAULT 5.0,
    mistake_weight INT DEFAULT 0,      -- يزداد تلقائياً عند تكرار الخطأ في نفس الآية
    next_review_at TIMESTAMPTZ,
    PRIMARY KEY (user_id, ayah_id)
);
```

## 7. خارطة الطريق التنفيذية على 5 مراحل (Execution Roadmap)

### المرحلة 1: التأسيس ومحرك المصحف التفاعلي (الأسابيع 1 – 2)
* إعداد هيكلية **Monorepo** والبيئة المشتركة بين الويب والجوال.
* بناء قاعدة بيانات القرآن الكريم كلمة بكلمة مع الترقيم العثماني والإملائي وتخطيط الـ 15 سطراً والوضع المتكيف.
* تطوير واجهة المصحف التفاعلية مع **وضع إخفاء الكلمات للتسميع (Hide Mode)** (إخفاء كلي، إظهار الحرف الأول، أو إظهار رؤوس الآيات) وميزة "التلميح عند التوقف" (Peek).

### المرحلة 2: البث الصوتي ومحرك التسميع اللحظي واكتشاف الأخطاء - MVP (الأسابيع 3 – 5)
* بناء خادم **FastAPI + WebSockets** ومدير الجلسات اللحظية.
* نشر حاوية الذكاء الاصطناعي الأولى (Silero VAD + `faster-whisper` بالنموذج القرآني المخصص).
* برمجة **خوارزمية المطابقة القرآنية (Fuzzy Aligner)** لاكتشاف الموضع تلقائياً، تحريك المؤشر كلمة بكلمة، ورصد التخطي والاستبدال والترديد.
* ربط التنبيهات الصوتية والبصرية وتخزين الجلسات.

### المرحلة 3: المنصة القرآنية الشاملة وأدوات الحفاظ (الأسابيع 6 – 8)
* **الخريطة الحرارية للأخطاء (Historical Mistakes Heatmap):** تلوين الكلمات التي يخطئ فيها الحافظ تاريخياً بتدرجات لونية لمعرفة مواضع الضعف.
* **مخطط الحفظ الذكي والمراجعة المتباعدة (FSRS Planner):** جدولة الورد اليومي والمراجعة تلقائياً بناءً على دقة التسميع الفعلي.
* **المشغل الصوتي المتزامن:** الاستماع لكبار القراء مع تظليل الكلمة المقروءة لحظياً وتكرار المقاطع للحفظ، مع عرض روابط **المتشابهات**.
* نظام رفع مقاطع تلاوة المستخدم كل 20 ثانية ودمجها لمشاركتها أو الاستماع إليها مع علامات الأخطاء على شريط الصوت.

### المرحلة 4: محرك تصحيح التجويد ومخارج الحروف (الأسابيع 9 – 11)
* دمج نموذج **Quran Phonetic Script (QPS / Multi-Level CTC)** في خادم الذكاء الاصطناعي.
* بناء محلل القواعد التجويدية لحساب أزمنة المدود والغنة وأحكام النون والميم الساكنتين والقلقلة.
* تصميم واجهة **"مختبر التجويد"**: تظليل الأحكام بالألوان، وتقديم تغذية راجعة دقيقة بعد كل آية (مثال: *"قصرتَ المد الواجب المتصل في كلمة ﴿ٱلسَّمَآءِ﴾ بمقدار حركتين والصواب 4-5 حركات"*).

### المرحلة 5: تطبيق الجوال، العمل دون إنترنت، والإطلاق الإنتاجي (الأسابيع 12 – 14)
* إتمام تطبيق **React Native** لـ Android و iOS بربط نفس المحرك البرمجي المشترك وقاعدة `SQLite` المحلية.
* إعداد ملفات النشر الإنتاجية (`Docker Compose` + `NVIDIA Container Toolkit` لخادم الـ GPU + `Nginx` + مراقبة الأداء عبر `Prometheus/Grafana`).
* اختبار الضغط (Load Testing) وتحسين زمن الاستجابة ليكون أقل من **250 مللي ثانية** من لحظة نطق الكلمة حتى ظهورها على الشاشة.

## 9. خطة البدء البرمجي الفوري في بيئة العمل الحالية (Step-by-Step Build Plan)

بما أننا اخترنا **وضع الخطة ثم الشروع في البرمجة الفعلية هنا**، فسوف نبني النواة الاحترافية القابلة للتشغيل والمعاينة الحية على النحو التالي:

1. **الخطوة البرمجية الأولى (النواة المتكاملة القابلة للتجربة فوراً):**
   * إنشاء هيكلية المشروع المعيارية النظيفة (`backend/` بـ FastAPI + `frontend/` بـ React/TypeScript + `docker-compose.gpu.yml` الجاهز لنشر خادم الـ GPU الخاص بك).
   * بناء **قاعدة بيانات القرآن الكريم الفعلية كلمة بكلمة** (الرسم العثماني + الإملائي + الصفحات + المتشابهات).
   * برمجة **محرك المطابقة واكتشاف الأخطاء والتجويد (`QuranAlignmentEngine`)** بالكامل في الخادم الخلفي عبر WebSockets (يتضمن البحث الصوتي التلقائي عن الآية، التتبع كلمة بكلمة، كشف التخطي والاستبدال والترديد، ومحاكاة/تحليل قواعد التجويد في الكلمات).
   * بناء **واجهة المصحف والمنصة الكاملة** بتصميم عربي احترافي يشمل:
     * المصحف التفاعلي + وضع إخفاء الكلمات للتسميع + التتبع الصوتي الحي عبر الميكروفون مباشرة في المتصفح (باستخدام طبقة ASR معيارية تعمل فوراً في المتصفح للمعاينة الحية وتدعم التحويل بزر واحد إلى خادم `faster-whisper` / `muaalem` المحلي الخاص بك!).
     * لوحة سجل الأخطاء والخريطة الحرارية، مخطط الحفظ والمراجعة، والبحث الصوتي القرآني.
2. **الخطوة البرمجية الثانية:**
   * تسليم حزمة خادم الذكاء الاصطناعي المستقل (`ai-worker/`) الجاهزة للتشغيل على أي خادم GPU خاص بك لتحميل نماذج `whisper-quran` و`muaalem-tajweed` وتشغيلها فعلياً بضغطة أمر واحدة (`docker compose up`).
3. **الخطوة البرمجية الثالثة:**
   * تجهيز حزمة تطبيق الجوال (`mobile/`) ومشاركة المحرك معها.
